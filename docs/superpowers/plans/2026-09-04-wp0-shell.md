# WP0 Tray/Permissions/Calibration Shell Implementation Plan

> **For agentic workers:** Execute inline in this Cloud Agent session. Spec is product-locked; do not wait for interactive approval.

**Goal:** Ship an empty Win/Mac-ready desktop shell (tray + permissions + calibration + settings) with Rust stubs for later vision/ASR/inject — no MediaPipe/ASR/injection.

**Architecture:** Cargo workspace with `workdance-core` (config, app state, inference stubs) and `workdance-desktop` (Tauri 2 app: tray, multi-window UI). UI is static HTML/CSS/JS matching Lumen dark lab-desk chrome; all future detection hooks stay in Rust.

**Tech Stack:** Rust 1.83+, Tauri 2, vanilla frontend (no framework), TOML config via `serde`/`toml`, GitHub Actions Linux CI.

## Global Constraints

- Keep/merge `docs/specs/2026-09-04-workdance-locked.md`; do not contradict it.
- WP0 only: no MediaPipe, ONNX, ASR models, SendInput/CGEvent, cloud APIs, Word adapters.
- Detection must NOT live in JS; Rust stubs only.
- Chinese labels where mockups use Chinese; dark lab-desk chrome.
- CI: `cargo check` (+ frontend build) on Linux; no camera hardware required.
- New PR only; do not merge.

## Why Tauri 2 (not pure Rust tray)

- Multi-window settings / permissions / calibration UI must match Lumen mockups; HTML/CSS is the fastest faithful path.
- Tray + window management are first-class in Tauri 2.
- Rust backend owns state and future vision/ASR/inject threads; JS is chrome only.
- Pure `tray-icon` + egui would be lighter but poorer mockup fidelity for Chinese multi-panel chrome in WP0.
